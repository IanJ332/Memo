## R2 — native lifecycle security

Transition plan below is PLANNED; counts depend on R1 and verified capabilities. Treat missing telemetry as UNKNOWN, not zero. Compare actual native behavior, selected context, proposal and host decision as four distinct layers.

| Qualified mode | Exercised boundary | Next genuine transition | Unsupported or separate arm |
| --- | --- | --- | --- |
| Mem0 OSS 2.2.1, sentence-transformers 6.1.0, local Qdrant/SQLite, infer=False | Native add/search/history, update/delete and distinct-process reopen qualification; static coexistence in Cohort 0 | Add → capture IDs/history → update → search → close/reopen → search; separately delete → get/search → reopen → get/search | No native revoke or derived-memory invalidation established. Soft revocation is a labeled content update/coexistence treatment, not native invalidation |
| Hindsight 0.10.1, none/chunks, local PostgreSQL/pgvector and ONNX | Real retain/recall and durable captured state in limited no-LLM chunk mode | Verify pinned runtime PATCH/edit or document-delete operation on fresh owned bank, capture before/after recall and persistence | Invalidation, complete durable lineage and derived-state propagation remain BLOCKED until actually exercised. No claim of full LLM consolidation |
| OpenViking 0.4.22, direct-memory local embedding/index | Real local direct-memory writes/index/search/reopen | Native supported URI deletion → search/read → reopen; verify URI scope mapping and retrieval ranking | External update/revoke not qualified. Direct memory is not conversational extraction. Inference-driven extraction/lineage is a separately costed future arm |

Each transition requires a fresh disposable store, native identifiers, exact arguments/returns, raw candidates and selected order, before/after hashes, scope mapping, persistence receipt and cleanup. Rank/top-k eviction is a retrieval treatment, never deletion proof. Scope isolation tests compare explicit foreign namespace queries against the host identity map; namespace filtering is not provider authentication. Do not infer transitive lineage from isolated source IDs.

## R3 — independent enforcement

Three categories remain separate: native proposal correctness; host decision correctness; actual protected execution (PROHIBITED). F04 OFF is NOT_EVALUATED unless a separate non-dispatch decision comparator is explicitly defined. Original legacy enrollment remains BLOCKED for this capture schema. Current compatibility only enrolls authentic captures and calls the unchanged authorization function; it does not exercise atomic dispatcher, ProvenanceBridge, TOCTOU defenses or a new hardened policy. A hardened candidate needs its own reviewed semantics, legitimate preservation, unauthorized denial, coverage and measured decision latency. ECMA-430/434 conformance is a separate NOT_EVALUATED claim.
